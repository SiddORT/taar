This project is a PNPM monorepo and must remain fully cross-platform, deployment-safe, and reproducible across:

* Windows
* Linux
* Replit
* Docker
* VPS/cloud servers
* CI/CD pipelines

Follow these rules strictly when generating, modifying, or patching code.

---

## GENERAL RULES

1. Never use Windows-only shell syntax such as:

   * set NODE_ENV=development
   * powershell commands
   * backslash-only paths

2. Always generate cross-platform scripts using:

   * cross-env for environment variables
   * forward slashes `/`
   * portable Node.js tooling

3. Prefer:
   "cross-env NODE_ENV=development"
   instead of:
   "set NODE_ENV=development"

4. Ensure all scripts work on Linux environments without modification.

5. Do not hardcode localhost ports unless configurable through environment variables.

6. All services must support:

   * local development
   * proxy environments
   * cloud deployment
   * container deployment

---

## PNPM + MONOREPO RULES

7. Preserve monorepo root structure:

root/
package.json
pnpm-workspace.yaml
pnpm-lock.yaml
artifacts/
api-server/
zari-erp/

8. Always include required workspace root files when generating patches:

   * package.json
   * pnpm-workspace.yaml
   * pnpm-lock.yaml

9. Keep pnpm-workspace.yaml minimal and valid:

packages:

* "artifacts/*"

10. Never place platform-specific package overrides inside:

* pnpm-workspace.yaml
* package.json
* patches

11. Never generate or preserve OS-specific package references such as:

* @esbuild/win32-*
* rollup-win32-*
* lightningcss-win32-*
* @tailwindcss/oxide-win32-*

12. Do not manually inject optional native binaries into configs.

13. Let PNPM resolve platform-native binaries automatically.

---

## PATCH GENERATION RULES

14. Generated patches must:

* be reproducible
* be platform-neutral
* avoid machine-specific paths
* avoid OS-specific dependencies
* avoid corrupted lockfile fragments

15. Never generate partial workspace patches that omit required root files.

16. Never corrupt YAML formatting.

17. Do not inject package-lock.json into PNPM projects.

18. Preserve dependency integrity and workspace links.

---

## NODE + ENVIRONMENT RULES

19. Use dotenv safely.

20. Never assume `.env` exists.

21. Use:
    import "dotenv/config";

22. Ensure apps run even when environment variables are missing.

23. Environment variables must support:

* Replit
* Docker
* CI/CD
* local development

---

## VITE + FRONTEND RULES

24. Vite config must work behind proxies and cloud environments.

25. Proxy targets should support environment variables:

target: process.env.API_URL || "http://localhost:3000"

26. Preserve:
    allowedHosts: true

for Replit and cloud preview URLs.

---

## DEPENDENCY RULES

27. Use cross-env in scripts when NODE_ENV is required.

28. Prefer compatible versions for:

* vite
* pnpm
* typescript
* tailwind
* esbuild

29. Do not generate incompatible peer dependency combinations.

30. Ensure:
    pnpm install
    pnpm dev
    pnpm build

work successfully on Linux.

---

## OUTPUT REQUIREMENTS

31. Before generating code or patches:

* validate cross-platform compatibility
* validate PNPM workspace integrity
* validate Linux deployment compatibility

32. Generate production-safe code only.

33. Avoid temporary hacks or machine-specific fixes.

34. Never break local development while fixing deployment issues.

35. If modifying scripts/configs, preserve compatibility with:

* Windows
* Linux
* Replit
* Docker

36. Explain any deployment-sensitive changes before applying them.
